# NC브레인 분석 보고서 — 푸른 AI CAM 개발 방향 참고용

- 작성일: 2026-11-27
- 목적: 사용자가 정식 라이선스로 보유한 NC브레인(NCBrain)이 현장에서 "편한" 이유를 파악하여, 푸른 AI CAM의 **기능·화면 흐름 방향**을 잡는 데 참고한다. 코드·화면·문구·템플릿을 복제하지 않고 **개념만** 참고한다.
- 분석 범위와 방법
  | 자료 | 방법 | 범위 |
  |---|---|---|
  | Drive "Nc브레인 도움말" | 사진 150장 판독 (OCR 138장 + 이미지 직접 확인 12장) | 도움말 페이지 약 96장, 실제 화면 약 50장, 장비 사진 4장 |
  | Drive "NCBrainV6.4.4" | 텍스트·설정 파일 읽기 | 포스트 섹션 65개, ini 21개, 장비 프리셋 16개 중 1개, 업그레이드 노트 3개, 도움말 토픽 52개 중 4개, 계약서 |
  | NC브레인 공식 홈페이지 | 웹 조사 | 아래 8장 참조 |
- **실행하지 않음**: NCBrain.exe, dll, 설치 파일, 바로가기는 내려받지도 실행하지도 않았다. 바이너리 파일(.mdl, .mod, .poc 등)은 이름과 크기만 기록했다.
- 분석은 개발 AI와 분리된 보조 에이전트 3개가 나누어 수행하고, 서로 내용이 맞는지 대조했다.

## 1. 한 줄 결론

NC브레인은 처음부터 끝까지 다 하는 CAM이라기보다 **"다른 CAM이 만든 NC를 불러와 시뮬레이션·최적화하고, 현장 서식에 맞춰 기계로 보내는 허브"**다. 여기에 **금형 몰드베이스용 2D CAM**(포켓·윤곽·드릴)이 들어 있다.

현장 작업자가 편하다고 느끼는 이유는 다음 다섯 가지로 정리된다.
1. **클릭 몇 번으로 치수 인식**: 선 4개 → 사각포켓, 지름·색으로 구멍 일괄 선택
2. **규격 하나로 공정 자동 연동**: M8을 고르면 센터 → 기초드릴 → 탭, 지름·깊이·피치가 자동으로 연동
3. **표 기반 자동 조건**: 지름별 S/F 표, HRC 단계 재질 보정, 추천 공구
4. **서식 자동화**: T번호만 넣으면 공구교환·좌표계·종료 블록이 자동으로 들어가고, 여러 NC를 한 파일로 묶는다
5. **현장 운영 기능**: 작업지시서, DNC/FTP 전송, 중단 지점 재전송, 좌표계 증가로 같은 부품 여러 개 가공

## 2. 제품 구조와 작업 흐름

### 2-1. 메뉴 구성 (V6 실제 화면 기준)
- 작업 / 보기 / 소재 / 경로 / 2D모델 / 3D모델 / 설정 / 도움말
- 설정 메뉴: 기계, 공구, 공구검색, 조도검색, 소재, 2D가공, 상세설정, 드릴, G코드 시작·끝
- 도움말 메뉴: 작업지시서(Ctrl+W), 질문과 답변, "알고있나요"(시작 시 팁)

### 2-2. 2D 작업 흐름 (도면 → NC)
1. **소재 정의**: 범위(X±, Y±, Z)와 재질(HRC 단계)을 정한다. 필요하면 클램프를 배치한다.
2. **도면 정리**: DXF·DWG를 열고 → 필요 없는 뷰를 드래그로 지우고(선택 반전 방식) → 중심선 두 개를 클릭해 교점을 원점으로 정한다 → 필요하면 회전·대칭한다. 결과를 저장한다.
3. **형상 정의**: 선·원을 클릭해 포켓·윤곽을 만든다. 구멍은 "지름 + 색"으로 한꺼번에 고르고, 고른 개수가 상태바에 표시된다.
4. **공정 생성**: 포켓은 공정 탭(드릴, 황삭, 중삭, 바닥, 측벽, 경사, 코너, 면취, 잔삭)을 체크한다. 구멍은 센터 → 드릴 → 탭을 한 번에 생성한다. 만든 공정은 작업 목록에 자동 등록된다.
5. **공구 확인**: 작업 목록 이름이 `T27-D33R6-초코-황삭-AIR`처럼 공구번호·지름·R·재질·공정·절삭유 형식으로 자동 표시된다.
6. **최적화·검증**: 소재 절삭 시뮬레이션, 이송 최적화, 과삭(빨강)·미삭(파랑), 공구 돌출 길이, 클램프 회피를 확인한다.
7. **출력**: 작업 파일로 저장하고 DNC·FTP로 전송한다. 여러 NC를 한 파일로 묶을 때 좌표계 증가(G54→G55…)나 반복을 고를 수 있다.

매뉴얼이 거듭 강조하는 원칙이 두 가지 있다. **"2D CAM 결과도 반드시 시뮬레이션으로 확인하고 사용"**, **"편집은 원본으로 하고 다른 이름으로 저장"**.

## 3. 구멍 가공 (푸른 AI CAM과 가장 직접 비교되는 부분)

| 항목 | NC브레인 | 푸른 AI CAM V0.2 | 차이·시사점 |
|---|---|---|---|
| 공정 구성 | 드릴 대화상자 하나에 센터드릴·드릴·볼트자리(카운터보어)·탭·모따기 체크박스 | 공정 묶음 프리셋(센터 → 드릴 → 탭) | 비슷한 개념. NC브레인은 **체크박스 하나로 공정 추가**라 더 빠르다 |
| 탭 연동 | M3~M32 콤보에서 M8을 고르면 기초드릴 지름·깊이(여유 자동 추가)·피치 자동 | 기초 드릴 **추천 표시와 검증**만. 공정은 프리셋으로 선택 | **"탭 규격 하나로 공정 세트 자동 생성"을 도입할 가치가 높다** |
| 관통 | "관통" 체크 시 소재 두께 자동 반영, "상대값" 옵션 | 관통 체크 + 하부 여유 검증 | 같음. 푸른 AI CAM은 하부 여유 검증이 더 엄격하다 |
| 구멍 위치 | 도면에서 지름+색으로 일괄 선택, 좌표 목록 편집, 좌표 텍스트 내보내기·읽기 | 직접 입력, 직선·사각·PCD 배열, 마우스 클릭 | **DXF 불러오기와 지름별 일괄 선택이 핵심 차이**. 좌표 텍스트 가져오기·내보내기는 쉽게 추가 가능 |
| 절삭 조건 | 지름별 S/F 표(드릴·센터·챔퍼 탭), 재질 HRC 단계 % 보정, 탭은 (F%+S%)/2 보정 | 재질 7종 × Vc·회전당 이송 공식 | 현장 사람은 **"지름별 표"가 더 익숙**하다. 표 편집 기능을 두면 공장 노하우를 반영하기 쉽다 |
| 펙 | 그림 위에서 점프 높이·첫 절입·절입량·횟수 입력 | Q값 입력(G73/G83) | 그림 기반 입력은 교육 효과가 크다 |
| 드릴 종류 | 드릴, U드릴, MAX드릴, 코너커터, 보링, 센터, 볼트머리, 모따기 | 센터, 드릴(HSS/초경), 탭 | 보링(M05/M03 코드), 볼트자리, 모따기는 확장 후보 |
| 탭 경고 | "탭 작업 시 회전수·이송 오버라이드 정확히 100%" 문구 | F = S × P 자동 계산과 검증 | **오버라이드 100% 경고를 NC 주석과 화면에 넣을 것** |
| 출력 방식 | DNC 미리보기에 G0/G1로 풀어 쓴 코드가 보임(불확실). 사용자 TAP 서식에는 `M29 S# / G84` 고정 사이클 사용 | 고정 사이클(G81~G84) 기본 | 현장 가독성과 교육 목적상 **고정 사이클 기본이 맞다** |

## 4. 포켓·윤곽 (다음 개발 단계 참고)

- **사각 포켓**: 선 4개를 고르고 깊이만 입력한다. 선 5개를 고르면 테이퍼 각도까지 자동 계산된다. 코너R, 회전각(도면에서 자동 인식), 아일랜드, "다중"(같은 크기 여러 개 한 번에)을 지원한다.
- **원형 포켓**: 원 4개를 고르고 바닥 깊이를 입력한다. "여러 개" 옵션으로 단이 진 원형 포켓을 표로 정의한다. "수직진입"은 기초 구멍이 있을 때 쓴다.
- **다각 포켓**: 선을 순서대로 고르거나, 좌표를 입력하거나, 마우스로 찍어서 만든다.
- **공정 탭 방식**
  - 드릴·황삭·중삭·바닥·측벽·경사·코너·면취·잔삭을 체크하면 한 번에 생성된다.
  - 공구는 자동 추천되고, 사용자는 지우거나 지름만 고친다.
  - **공정 설정을 파일로 저장·불러오기**한다.
  - 진입은 헬리컬·직선·수직, 바닥 두 번 가공, 측벽 경보정(G41 D1), 잔삭(더 작은 공구로 코너만)을 지원한다.
- **윤곽**: 선을 순서대로 고르면 방향 화살표가 표시된다. 공구 위치(좌·우·중심), 1회 절입, 측면 피치, 시작·끝 연장, 접근(직선/원호)을 정한다.
- **경로 복사**: 윤곽 경로 하나를 골라 둔 원 위치마다 복사한다. 패턴 배열을 일반화한 형태다.

## 5. 포스트(ATC 서식) 구조와 장비 설정

### 5-1. 구조
- NC브레인의 포스트는 장비 운동학을 다루는 블록형 포스트가 아니다. **머리·꼬리 서식 템플릿**을 NC에 씌우는 방식이다.
  - 섹션: 일반 Begin/End, AtcBegin/AtcEnd, Main(여러 NC를 부르는 메인), Measure(공구 측정)
- **파일명 규칙**: `[세트번호][컨트롤러][Atc|Main](Begin|End)[변형]`
  - 예: `2GcodeAtcBegin0M` = TAP 세트의 FANUC 0M 계열 공구교환 시작 서식
  - 세트 슬롯: 0=절삭유, 1=AIR, 2=TAP, 3=AIR1, 4=TAP1 (사용자 설정)
  - 컨트롤러: Gcode(FANUC), Heiden(하이덴하인), Simens(지멘스), RoedersGcode(뢰더스), 5Axis(G68.2)
  - 변형 접미사: 0M(일반), G051Q1(선독), G05P10000(고속 가공), Measure(측정)
- **자리표시자**: `f#`(파일명), `d#`(지름), `r#`(코너R), `t#`(여유), `T#`, `H#`, `S#`, `X#Y#`, `Z#`, `Sb#`(직경−R, 측정기용), `tn#`(ATC 번호), `O#`(프로그램 번호 증가) 등
  - 조건문은 없다. 조건은 **파일 선택과 옵션**으로 처리한다(T번호별 시작 파일, 직경 기준 변수 삭제 등).
- **출력 형식 옵션**: 소수점 자리, N번호(G0 앞에만 붙이기 등), 원호 R/IJK, 모달 생략, 코드 치환·삭제·추가, 그대로 통과시킬 코드(측정 매크로), 확장 좌표계(G54.1 P1~48), 확장자.
- **장비 설정**: 최대 회전수·이송·가속, 공구 재질별 %, 직경별 rpm, 급속 높이, 홀더 단면, 4·5축 회전축(테이블형·헤드형, 고정 경사각 30° 등).
  - 장비 프리셋 16개: BT30/40/50 × L/M/H, 흑연, 프레스, 소형 고속가공.
- **재질 보정**: 흑연, 알루미늄, 구리, HRC18~50별 이송·회전 %.

### 5-2. 사용자 설정에서 확인된 현장 실무 (협력업체 장비 이해에 도움)
- 기계 고유 M코드를 쓴다: `M200T#`(가공 전 공구 측정), `M300T#`(가공 후 측정, 차이가 0.2를 넘으면 정지), `M140/M141`.
- TAP 세트에 `M29 S# / G84 G98 …` 시작부와 `G80 M28` 끝부분이 있다. 이 장비는 **리지드 탭 해제에 M28**을 쓰는 것으로 보인다. 협력업체 장비 확인 항목에 추가해야 한다.
- 고속 가공 모드(G05P10000 / G5.1Q1)는 공구교환 전과 끝에서 해제한다.
- 사진에 찍힌 장비: FANUC 31i-A, 18i-MB 컨트롤러, VX750M, RHINO LCV66.
- 같은 폴더의 `JINSUN.OPT`는 NC브레인 파일이 아니라 Delcam **DuctPost** 계열 블록형 포스트 옵션 파일로 보인다. 공구교환 시 `G05P10000`, 끝에 `M99`를 쓴다.

### 5-3. 보안 주의 (사용자 조치 필요)
- `ini/dnc.ini`에 **FTP 계정과 비밀번호가 평문으로** 저장되어 있다. 보고서에는 옮기지 않았다.
- `media.ini`, `view.ini`에는 고객사 작업 경로가 들어 있다.
- 이 Drive 폴더를 다른 사람과 공유하지 말고, 공유했다면 **해당 FTP 비밀번호를 바꿀 것을 권장**한다.

## 6. 현장 편의 기능 목록 (NC브레인이 편한 이유)

| 분류 | 편의 기능 |
|---|---|
| 도면 | 선택 반전으로 뷰 정리, 교점 클릭 원점, Shift+클릭 후 Space로 연결선 전체 선택, 트림 자동 분할 |
| 인식 | 선 4개 → 사각포켓, 선 5개 → 테이퍼 각, DXF 위·아래 선 → XYZ 치수, 지름·색 일괄 선택 + 개수 표시 |
| 공정 | 체크박스로 공정 추가, 추천 공구, 공정 설정 저장·불러오기, 생성물 자동 이름(-cp 등)과 작업 목록 자동 등록 |
| 구멍 | 탭 규격 → 기초드릴·깊이·피치 자동, "관통" 한 번 체크, 좌표 텍스트 내보내기·읽기 |
| 조건 | 지름별 S/F 표, HRC 단계 재질, 공구 재질별 %, 장비 프리셋 |
| 공구 | 공구 라이브러리, 공구 이름 규칙 학습(공구검색어), 작업 목록에 공구 요약 표시, 돌출 길이 L > 4D 경고·분할 |
| 출력 | T번호만 넣으면 서식 자동, 컨트롤러 기본값 버튼, 여러 NC 한 파일 묶기, 좌표계 증가·반복, 파일명 영문 변환 |
| 운영 | 작업지시서 자동(공구 목록·소재·시간), DNC·FTP 전송, 중단 지점 재전송, 최적화 후 DNC 목록 자동 추가, 시간 기준 M00 삽입 |
| 안전 | 클램프 배치 → G00 높이 자동 회피, 과삭·미삭 색 표시, 탭 오버라이드 경고, 깊은 면취 확인 경고 |
| 학습 | 시작 시 팁("알고있나요"), F1~F7·Ctrl 단축키, 우클릭 메뉴, "상세히" 체크로 고급 옵션 펼치기 |

## 7. 푸른 AI CAM 개발 방향 제안

### 7-1. 바로 적용 (V0.3 후보, 구멍 가공 강화) — 우선순위 순
1. **탭 규격 마법사**: M규격(+보통/가는 나사)과 깊이 하나만 고르면 센터 → 기초드릴(추천 지름, 깊이 = 탭 깊이 + 여유) → 탭(피치 자동) 공정 세트가 생성되게 한다. 이미 있는 기초 드릴 추천 표·검증과 연결한다.
2. **탭 오버라이드 100% 경고와 고속 모드 해제**: NC 주석 `(TAP: SET FEED/SPINDLE OVERRIDE 100%)`과 다운로드 확인창에 넣는다. 장비 프로필에 고속·선독 모드(G05.1 Q1 등)가 있으면 탭 앞에서 해제하고 끝난 뒤 다시 켜도록 자동 출력하고, 독립 검증기로 검사한다(8-4 참조).
3. **공정 자동 이름**: 공정 카드와 NC 주석을 `T05-D6.8-드릴-펙` 같은 형식으로 표시한다.
4. **지름별 절삭조건 표(편집 가능)**: 지금의 공식 기반 추천은 그대로 두고, 공장이 자기 표를 입력하면 그 표를 우선 쓰게 한다(지름 사이는 보간). 재질은 교육용 단계(알루미늄 / SM45C / SKD11 / 열처리강)도 함께 제공한다.
5. **좌표 텍스트 가져오기·내보내기**: 측정기나 다른 프로그램의 XY 목록을 붙여넣어 홀을 만든다.
6. **작업지시서 출력**: 공구 목록(T, 종류, 지름, 날장), 소재·원점, 공정 순서, 홀 개수, 예상 시간, 화면 이미지를 인쇄용 HTML로 만든다. 현장에서 공구를 미리 준비할 수 있다.

### 7-2. 다음 단계 (V0.4~, DXF와 포켓)
7. **DXF 불러오기**: 뷰 정리(선택 반전) → 교점 클릭 원점 → 원을 지름(+레이어·색)으로 일괄 선택하고 개수 표시 → 홀 그룹으로 변환. 구멍 위주라 DXF의 LINE·CIRCLE·ARC만 먼저 지원해도 효과가 크다.
8. **포켓·윤곽은 "공정 체크 + 추천 공구 + 설정 저장" 방식**으로 만든다. 단, 약어 탭(fb, fw, co) 대신 한글 이름을 쓰고, 고급 옵션은 "상세" 버튼 안에 숨긴다.
9. **경로 복사**: 한 공정을 고른 원 위치들로 복사하는 일반화된 배열.
10. **NC 검증기 확장 선행**: 포켓·윤곽은 G01/G02/G03 절삭 경로이므로, 지금의 독립 검증기에 절삭 이동 검증(소재·클램프·깊이·공구 반경)을 먼저 추가해야 출력 차단 원칙을 지킬 수 있다.

### 7-3. 포스트·장비 설정 설계
11. **자리표시자 템플릿 + 조건문**: NC브레인은 변형마다 파일을 만들어 템플릿이 65개까지 늘었다. 푸른 AI CAM은 하나의 포스트 프로파일 안에 섹션(시작, 공구교환, 공정, 사이클, 끝)을 두고 이름 있는 변수(`{TOOL_NO}`, `{SPINDLE}`)와 조건(`{#if COOLANT=air}`)으로 처리한다.
    - `#` 한 글자 표기는 FANUC 매크로 변수(#1, #500)와 충돌하므로 쓰지 않는다.
12. **장비 프로필에 현장 코드 추가**: 리지드 탭 해제 코드(G80 뒤 M28 여부), 고속 가공 모드 코드와 해제 위치, 공구 측정 매크로(M200 같은 장비 고유 코드), 확장 좌표계(G54.1 P1~48). **사용자 추가 코드도 독립 검증기의 허용 목록에 등록해야** 출력할 수 있게 해서 안전 원칙을 유지한다.
13. **좌표계 증가 출력**: 같은 부품 여러 개(G54→G55→G56…)를 한 프로그램으로 출력한다. 실습 수업에 유용하다.
14. **보호된 기본 프로파일**: 공장 기본값은 읽기 전용으로 두고, 사용자 사본만 편집하게 한다. "FANUC 기본값 복원" 버튼을 둔다.
15. **비밀정보 분리**: 앞으로 FTP 전송을 넣더라도 비밀번호는 설정 파일과 백업에 평문으로 저장하지 않는다(NC브레인 dnc.ini의 반면교사).

### 7-4. 하지 않을 것
- NC브레인의 핵심인 **부하 기반 이송 최적화와 3D 과삭·미삭 검사를 흉내 내는 것**은 소규모 공장용 웹 CAM 범위 밖이다. 비용 대비 효과도 낮다.
- 메뉴 20여 개를 나열하는 구조, µm 단위 입력칸, 의미를 알기 어려운 약어는 피한다.
- **NC브레인의 화면, 아이콘, 문구, 템플릿 내용, ini 키 이름 체계를 그대로 옮기지 않는다.** 계약서가 리버스엔지니어링·디컴파일을 금지하므로 바이너리는 분석하지 않는다(이번 분석에서도 하지 않음).
- 근거 없는 효과 수치("가공시간 30% 단축" 등)를 홍보하지 않는다.

## 8. 공식 홈페이지 조사

### 8-1. 조사 한계 (먼저 확인)
- 공식 사이트(www.ncbrain.com, ncbrain.co.kr, ncbrain.com.cn, ncbrain.cn)는 **평문 HTTP 전용**이다. 이 클라우드 작업 환경은 HTTPS(443)만 통과시키므로, 주소를 허용 목록에 추가한 뒤에도 페이지와 PDF를 **직접 열지 못했다**. 보안 검증을 끄는 우회는 하지 않았다.
- 따라서 이 장의 내용은 모두 **검색엔진이 보여 준 공식 페이지 요약·발췌**에 근거한다. 원문 문구와 세부 메뉴명은 다를 수 있다.
- 직접 확인하려면 사용자가 PC 브라우저로 공식 사이트를 열어, 필요한 페이지를 PDF·캡처로 Drive에 올려 주면 된다. 그러면 앞 장과 같은 방식으로 분석할 수 있다.

- **4대 스마트기술**: 데이터베이스(기계·소재·공구 노하우), 자동화(2D 몰드베이스 CAM, AICAM), 시뮬레이션(3~5축 충돌), 최적화(이송·회전수·경로).

  - DXF/DWG 입력

  - 프레스 금형 상대 깊이 자동 가공
- **현장 편의**
  - T번호만 입력하면 ATC 서식 자동
  - 공정 순서 재배열 후 한 파일 전송
  - 작업지시서 자동 생성(공구, 소재 크기, 가공 전후 중량, 엑셀·이미지)
  - 내장 FTP
  - 공구 이름 규칙 학습(공구검색어)
  - 한글 미지원 기계용 영문 파일명
  - 자동 팁
- **FAQ에서 얻은 실무 교훈**
  - **탭 가공 알람은 선독(look-ahead) 제어를 해제하면 대부분 해결**된다는 안내가 있다(G05 P10000 / G5.1 Q1 해제).
    - 사용자 설정 파일에서도 고속 가공 모드를 공구교환 전후로 해제하고 있다. 장비 고속 모드와 탭이 충돌할 수 있다는 근거다.
  - 도면 선이 길게 연장되어 있으면 포켓이 생성되지 않는다. 교차점에서 선을 자르는 도면 정리가 사용 흐름에 들어 있다.
  - 설정은 INI 파일 기반이다. 소재 DB 전환을 파일 이름 바꾸기로 하는 등 화면 밖 설정이 많다.
- 포스트 섹션 파일(GcodeAtcBegin 등)을 설명하는 공식 문서는 **웹에서 찾지 못했다**. 5장의 구조 분석은 사용자 설치본 파일을 직접 읽은 결과다.

### 8-4. 공식 조사에서 추가된 제안
- **[7-1 보강] 탭 전 고속 모드 해제**: 장비 프로필에 "고속·선독 모드 코드(예: G05.1 Q1)와 해제 코드"를 두고, 탭·리지드 탭 공정 앞에서 자동으로 해제한 뒤 다시 켜게 한다. 독립 검증기도 "고속 모드 상태에서 G84"를 오류로 검사한다.
- **[7-3 보강] 설정은 화면에서**: NC브레인처럼 숨은 INI와 파일 이름 바꾸기로 바꾸는 방식이 아니라, 모든 장비·재질·포스트 설정을 화면에서 편집하고 앱 안 도움말로 설명한다(현재 푸른 AI CAM 방식 유지).
- **[장기] 외부 NC "허브" 기능**: NC브레인 사용자의 주 용도는 "다른 CAM이 만든 NC를 불러와 서식을 씌워 기계로 보내기"다. 푸른 AI CAM에는 이미 독립 NC 검증기가 있으므로, **외부 NC를 불러와 검증하고 경로를 보는 기능**은 비교적 적은 노력으로 큰 효과를 낼 수 있다. 단, 지금 검증기는 홀 가공 코드만 해석하므로 G01/G02/G03 해석 확장이 먼저 필요하다.
