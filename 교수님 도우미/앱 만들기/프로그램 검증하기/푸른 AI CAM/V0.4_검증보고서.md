# 푸른 AI CAM V0.4 검증 보고서

- 대상 버전: **V0.4** (`교수님 도우미/앱 만들기/프로그램 변경하기/푸른 AI CAM/V0.4/`)
- 변경 전 버전: V0.3 (`…/프로그램 변경하기/푸른 AI CAM/V0.3/`, 보존·미변경)
- 검증일: 2026-11-27
- 검증 환경: Linux 컨테이너, Node.js 22, Playwright + Chromium. 3D 는 SwiftShader 소프트웨어 WebGL 로 확인했다. 윈도우 크롬·엣지, 실제 GPU, 실제 FANUC 장비는 사용하지 않았다.
- 결론:
  - 독립 안전 검토가 찾은 치명 2건·주요 5건과 경미 항목 일부를 고쳤다. 디자인 검토의 높은 우선순위 항목 6건과 중간 항목 대부분도 반영했다.
  - 각 수정은 재현 테스트로 확인했다.
  - **실장비 검증 전이므로 출력 NC 는 계속 "검증용(TEST)" 이다.** 포켓 가공은 특히 시편으로 먼저 확인해야 한다.

## 5. 원본·기존 기능 영향
- V0.1, V0.2, V0.3 폴더는 변경하지 않았다.
- 기존 기능은 모두 유지된다: 구멍·탭 간편 입력, 직접 구성, 공정 묶음, 배열, 클램프, 검증·차단, 관리자, 공유, 백업.
- 데이터 형식은 같다(schema 1).
- **되돌리기 주의**: V0.4 데이터를 V0.3 에서 열면 다음 일이 생긴다.
  - 포켓 공정은 경고와 함께 제외된다.
  - **평 엔드밀(T16~T19)이 드릴로 읽힌다** (실행으로 확인).
  - 따라서 V0.3 으로 되돌릴 때는 엔드밀 공구를 먼저 삭제해야 한다(버전기록에 명시).

## 6. 남은 위험·미검증
1. **실장비 미검증**: 포켓 헬리컬 진입(G03 + Z) 지원 여부와 파라미터(원호 반경 오차 허용값)는 장비마다 다르다. 첫 가공은 드라이런 → 싱글 블록 → 시편 순서로 진행해야 한다.
2. 독립 검증기가 소재 상태를 완전히 알지 못한다. 수정한 NC 의 급경사 램프와 한 번에 전체 깊이를 깎는 경로는 막지 못한다. 생성된 NC 에서는 생기지 않는다.
3. 절삭 조건(엔드밀 Vc·fz·절입)은 일반적인 참고값이다. 공구 제조사 값으로 확인해야 한다.
4. 예상 가공 시간은 가감속·주축 가속을 반영하지 않은 추정치이다.
5. 3D 시뮬레이션은 다음 한계가 있다.
   - 높이맵 근사이며, 홀더 간섭과 나사산 모양은 반영하지 않는다.
   - 실제 GPU 와 윈도우 브라우저에서 확인하지 않았다.
   - WebGL 이 없으면 2D 만 사용할 수 있다.
6. 화면 검토는 AI 관점의 검토이다. 실제 작업자·학생의 사용성 확인이 필요하다.
