# 푸른 AI CAM V0.6 검증 보고서

- 대상 버전: **V0.6** (`교수님 도우미/앱 만들기/프로그램 변경하기/푸른 AI CAM/V0.6/`)
- 변경 전 버전: V0.5 (`…/프로그램 변경하기/푸른 AI CAM/V0.5/`, 보존·미변경)
- 검증일: 2026-11-28
- 검증 환경:
  - 사용: Linux 컨테이너, Node.js 22, Playwright + Chromium (3D 는 SwiftShader 소프트웨어 WebGL).
  - 사용하지 않음: 윈도우 크롬·엣지, 실제 GPU, 실제 FANUC 장비.
- 근거: V0.6 은 `V0.6_추가기능_전문가분석.md` 로드맵의 1단계(실가공 준비 + 처음 쓰는 사람)다.
- 결론:
  - 독립 안전 검토 결과 치명은 0건, 주요는 6건이었다. 주요 6건과 경미 지적 대부분을 고친 뒤 재현 시험으로 확인했다.
  - 엔진 테스트 150개와 브라우저 통합 테스트 128개가 모두 통과했다.
  - V0.5 대비 1,000건 비교(밀링 포함)에서 G코드가 같다. 차이는 NC 해시 줄 하나뿐이다.
  - **실장비 검증 전이므로 NC 는 계속 "검증용(TEST)" 이다.** 이번 버전은 그 TEST 를 정식으로 해제하는 절차(첫 가공 모드 → 시편 → 가공 종류별 승인)를 갖췄다.

## 5. 원본·기존 기능 영향
- V0.5 폴더는 변경하지 않았다.
- 기존 가공의 G코드는 V0.5 와 같다. 머리말에 `(NC HASH …)` 줄 하나가 늘었다.
- 저장 형식은 같다(schema 1). 새 필드는 이전 버전이 무시한다: 장비 `approvals`·`history`, 공구 `stick`·`holderDia`·`hVal`, 설정 `firstRun`·`restart`·`g54Z`, 기록 `records`.
- **의도한 변경**: V0.5 이하에서 장비를 "검증 완료"로 승인했어도, V0.6 에서는 가공 종류별로 다시 승인해야 TEST 가 사라진다.

## 6. 남은 위험·미검증
- **실장비 미검증**: 첫 가공 모드, 재시작 블록, 리머(G85), 보링(G76·G86)은 장비에서 확인하지 않았다.
  - G76 의 Q 이동 방향은 장비 파라미터(FANUC 5101)에 따라 다르다. 보링 바 날 방향과 꼭 맞춰야 한다.
  - M00 이 주축·절삭유를 멈추는지는 장비마다 다르다. 연속 공정에서는 다시 지령한다.
- **재시작 블록 사용법**: 장비의 시퀀스 번호 검색(프로그램 재개) 기능으로 해당 N번호부터 다시 시작한다. 재개 전에 공구 길이·좌표계·주축을 작업자가 확인해야 한다. 검증기는 재개 경로를 따로 시뮬레이션하지 않는다.
- **공구별 분할 파일은 순서대로만 실행**해야 한다 (파일 안 주석에 표시).
- **NC 해시는 추적용**(FNV-1a)이며 위변조 방지용이 아니다.
- **홀더 간섭 검사는 입력값에 달려 있다**: 돌출 길이·홀더 지름을 넣은 공구만 검사하고, 머신 Z 행정은 G54 Z·H 값을 넣었을 때만 검사한다. 넣지 않으면 안내만 한다.
- **3D 는 소프트웨어 WebGL 로만 확인**했다.
