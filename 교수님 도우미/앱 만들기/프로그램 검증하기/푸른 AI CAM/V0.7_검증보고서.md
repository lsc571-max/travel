# 푸른 AI CAM V0.7 검증 보고서

- 대상 버전: **V0.7** (`교수님 도우미/앱 만들기/프로그램 변경하기/푸른 AI CAM/V0.7/`)
- 변경 전 버전: V0.6 (`…/프로그램 변경하기/푸른 AI CAM/V0.6/`, 보존·미변경)
- 검증일: 2026-11-28
- 검증 환경:
  - 사용: Linux 컨테이너, Node.js 22, Playwright + Chromium (3D 는 SwiftShader 소프트웨어 WebGL).
  - 사용하지 않음: 윈도우 크롬·엣지, 실제 GPU, 실제 FANUC 장비, 실제 사용자(사람) 사용성 시험.
- 요청: "기능이 많아져 화면이 복잡하다. 처음에는 필요한 것만 보이고 누르면 더 보이게. 다른 것은 건드리지 말고 화면 구성과 디자인만. 아이콘은 더 크고 눈에 띄게. 화면 전문가 3명 + 시각 디자인 전문가 3명."
- 결론:
  - **화면 파일 3개만 바꿨다.** 가공 엔진·포스트·검증기·시뮬레이션 소스는 V0.6 과 같다 (버전 문자열 한 줄 제외, 자동 시험으로 확인).
  - V0.6 대비 1,000건 비교에서 자동 구성 공정·검증 결과·G코드·독립 검증 결과가 같다.
  - 엔진 테스트 152개, 브라우저 통합 테스트 172개가 모두 통과했다.
  - 독립 검증 AI 2개가 치명 0건, 주요 10건(기능·안전 표시 4, 화면 6)을 지적했다. 주요 10건을 모두 고치고 재현 시험을 넣었다 (4절).
  - **실장비 검증 전이므로 NC 는 계속 "검증용(TEST)" 이다** (V0.6 과 같음).

## 2. 전문가 6인 안과 반영
개발 전에 서로 다른 관점의 AI 6개가 V0.6 화면(1440×900·1280×720·휴대폰 캡처)과 코드를 보고 각자 안을 냈다. 실제 사람 전문가 패널이 아니라 AI 관점 분석이다.

| 전문가 | 핵심 제안 | 반영 |
|---|---|---|
| 화면 ① 정보 구조 | 속성 패널을 치수부터 시작, 3단계(항상/한 번 눌러/고급), 접힌 줄에 값 요약 | 반영 |
| 화면 ② 작업 흐름 | 흐름 한 줄, 다음 할 일을 동사로 크게, 추가 버튼 하나 + 선택판 | 반영 |
| 화면 ③ 인지 부하 | 첫 화면 조작 요소 72 → 30 이하, 중복 표시 줄이기, 숨긴 것은 2번 안에 닿게 | 포켓 76 → 52, 예제 73 → 56 (목표 30 에는 못 미침 — 6절) |
| 디자인 ① 아이콘 | 가공 8종을 실루엣으로 구분, 색 타일 위 큰 아이콘 | 반영 (18개) |
| 디자인 ② 시각 위계·글씨 | 글씨 단계 4개, 최소 13px, 겹친 테두리·카드 줄이기 | 반영 |
| 디자인 ③ 색·강조 | 브랜드 색은 주 버튼에만, 종류 색은 타일 바탕에만, 대비 4.5:1, 모따기 색을 오류 빨강과 구분 | 반영 |

## 5. 원본·기존 기능 영향
- V0.6 폴더는 변경하지 않았다.
- 가공 결과(NC)는 V0.6 과 같다. 머리말의 버전 주석(`PUREUN AI CAM V0.7`)과 그에 따른 해시 줄만 다르다.
- 저장 형식은 같다(schema 1). 브라우저 설정에 `dense`(모두 펼쳐 보기) 한 칸이 늘었고, 이전 버전은 무시한다.
- **의도한 변경**
  - V0.6 에서 받은 가공 종류별 승인은 앱 버전이 바뀌어 V0.7 에서 다시 승인해야 TEST 가 사라진다 (V0.6 에서 정한 규칙 그대로).
  - 새로 만드는 모따기·리머·보링·평면 가공의 기본 표시 색이 바뀌었다 (오류 빨강·서로와 구분). 이미 있는 가공의 색은 그대로다.
  - 목록 아이콘 바탕이 표시 색에서 가공 종류 색으로 바뀌었다 (표시 색은 작은 점).
  - 알림이 몇 초 뒤 저절로 사라진다 (V0.5·V0.6 은 계속 남았다).
  - 입력칸 오류가 붙는 칸이 일부 달라졌다 (예: 경로 간격 오류가 공구 칸이 아니라 경로 간격 칸에).
  - 포켓 [가공 단계]는 체크 상자 대신 단계 칩을 눌러 켜고 끈다 (값은 같음).

## 6. 남은 위험·미검증
- **사람이 직접 써 본 사용성 시험은 하지 않았다.** "간단해졌는지"는 조작 요소 수·패널 길이 같은 측정값과 AI 검토로만 확인했다. 실제 사용자가 접힌 줄을 잘 찾는지는 써 보고 확인해야 한다.
- **첫 화면 조작 요소 47~56개**: 전문가가 제시한 목표 30개에는 못 미친다. 구멍 가공은 위치 입력을 처음부터 펼쳐 두었고, 작업 순서 5단계와 패널 접기 버튼을 남겼기 때문이다.
- **접힌 줄 안의 설정은 한 번 더 눌러야 한다.** 자주 쓰는 사람은 [설정] → [모두 펼쳐 보기]를 켜면 된다.
- **실장비 미검증** (V0.6 과 같음): 첫 가공 모드, 재시작 블록, 리머(G85), 보링(G76·G86).
- **3D 는 소프트웨어 WebGL 로만 확인**했다. 윈도우 크롬·엣지 실제 화면은 확인하지 않았다.
