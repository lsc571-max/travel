# 오픈소스 CAM·커뮤니티 분석과 V0.4 반영 내역

> 분석 방법 (2026-11-27)
> - 공개 저장소 소스와 문서를 **읽기만** 했다. 받은 코드는 실행하지 않았다.
> - **코드와 문구는 옮기지 않았다.** FreeCAD·jsCut·bCNC·CAMotics 는 GPL/LGPL, Kiri:Moto 는 MIT 이며, 개념만 참고했다.
> - 커뮤니티 의견은 웹 검색 결과 요약과 FreeCAD 개발진의 자체 로드맵 문서를 근거로 삼았다. 일부 사이트(Reddit·estlcam.de·GitHub 이슈 검색)는 현재 네트워크 정책 때문에 직접 열람하지 못했다.
> - 표기: [확인] 소스·문서를 직접 읽음 / [검색] 검색 결과 요약 / [추정] 판단.

## 1. 조사 대상

## 2. 사용자들이 불편해하는 점 (커뮤니티·개발진 자체 평가)
1. 작업(Job) 시작 단계가 복잡하고, 좋은 기본값 기능이 숨어 있다 [확인: FreeCAD Roadmap].
2. 용어가 작업마다 다르다. 예: 남김 여유 / Stock to leave / Offset [확인].
3. 진입 방식이 후처리(Dressup)에 숨어 있고 이름이 `RampMethod1~4` 처럼 의미가 없다 [확인].
4. 점검(Sanity)을 수동으로 돌려야 한다. 시뮬레이터에 원점 표시가 없고 충돌·과삭 감지도 없다 [확인].
5. 공구와 조건이 작업과 떨어진 화면에 있어 고치려면 작업을 나가야 한다 [확인].
6. 구멍을 조용히 빠뜨리는 경우가 있다. 예: R점이 바닥보다 낮을 때 [확인: FreeCAD 경고 로직].
7. 시뮬레이션이 실제 출력 G코드가 아니라 내부 명령을 보여 준다 [확인].
8. 커뮤니티 요청: 공통 정보(원점·좌표계·안전 높이)를 먼저 고정하고 싶다, 사이클을 고른 이유를 알고 싶다, 직선 수직 진입은 기본으로 막아 달라, 읽기 쉬운 G코드, 사이클 타임과 그 한계 고지, 셋업시트 인쇄, 시뮬레이션의 가정 표시, 한국어 용어에 원어를 함께 적어 달라 [검색].

## 4. 이번에 반영하지 않은 것 (다음 단계 후보)
- 지름이 같은 구멍 자동 묶음과 "같은 지름 모두 선택". 도면(DXF) 가져오기가 생기면 의미가 있다.
- 작업 목록의 "여기까지만" 바: 부분 시뮬레이션·부분 출력용.
- 마지막 사용값을 다음 기본값으로 기억하기.
- 미가공·잔량 색상 표시(목표 깊이 대비 편차), 홀더·생크 간섭 검사.
- 공구별 NC 분할 저장, 가감속을 반영한 시간 추정.
