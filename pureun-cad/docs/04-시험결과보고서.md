# 04. 시험 결과 보고서 — 푸른캐드 V0

- 시험일: 2026-11-27
- 시험 환경: Linux 클라우드 컨테이너(Intel Xeon 2.10GHz, 4코어), Node 22.23.5, Chromium(Playwright 내장, headless·소프트웨어 렌더링), Python 3 + ezdxf 1.4.5
- **실제 AutoCAD는 이 환경에서 실행할 수 없어 AutoCAD로 여는 시험은 하지 않았습니다.** 대신 독립 구현인 ezdxf(MIT)의 엄격 읽기 + `audit()`로 저장 파일을 검사했습니다.

### 2.2 화면 시험 (Playwright, `npm run e2e`) — 20/20 통과

1. 명령창 작도 REC/CIRCLE(D 옵션)/LINE(극좌표·상대좌표)
2. 객체 스냅으로 정확한 좌표 지정(끝점 (0,0), 중심점 (30,40)) + U
3. 직교(F8) + 직접 거리 입력 35 → (35,-10)
4. 창 선택 1개 / 걸치기 선택 2개
5. MOVE(선택 후 실행), COPY 2회 + 실행취소 1회로 전체 취소, ROTATE 90°
6. TRIM: 두 원 사이 선 제거 → 끝점 x=40, 80 정확
7. OFFSET 사각형 바깥 5 → 꼭짓점 정확히 (-5,-5)…(125,85)
8. 치수 선형(커서 위치로 수직 자동 판별)·지름·반지름
9. 동일 지름 원 일괄 변경 Ø20→Ø16(중심 유지) + 실행취소
10. 레이어 생성·현재 지정·잠금 → ERASE ALL 시 잠긴 객체만 남음
11. DXF 저장(R12) → 새 도면 → 열기 왕복 일치 + **ezdxf 감사 오류 0**
12. **실무 도면** flange_R2000(코드페이지 표기와 실제 인코딩이 다른 한글 파일) 열기 → 미지원 객체 경고 → 볼트 구멍 8-Ø14→Ø13.5 일괄 변경(중심 유지) → 잠금·숨김 레이어 객체 보호 → 근사 변환 포함 저장 → **ezdxf 감사 오류 0**
13. 설정 1회 클릭 → 일반 설정(비밀번호·API 항목 없음)
14. 설정 아이콘 4회 + 3초 초과 후 1회 → 관리자 창 열리지 않음
15. 3초 안에 5회 → 비밀번호 등록 → 관리자 설정, localStorage에 원문 없음
16. 오답 5회 → 잠금, 인증 없이 통과 불가
17. 접근성 대체 경로: 키보드 초점 + Enter 5회 → 관리자 인증 창
18. 공유 QR 이미지 생성(330px 이상), 버전 확인 "최신 버전" 응답
19. 계산 불가 OFFSET(반지름 초과) → 오류 메시지, 객체 수 변화 없음
20. 전체 시험 중 브라우저 콘솔 오류 0건

## 3. DXF 호환성 (실무형 시험 도면)

시험 도면은 푸른캐드와 무관한 독립 라이브러리(ezdxf)로 생성: `tests/fixtures/make_fixtures.py`.
내용: 플랜지 외경 Ø200·내경 Ø80, PCD150 볼트 구멍 8-Ø14, 반원 슬롯(bulge 폴리선), 중심선(CENTER), 호, 잠금·꺼짐 레이어, 한글 문자 `플랜지 8-%%c14 PCD150`, 선형·지름·반지름 치수 / (R2000 이상) 블록 참조 2개(회전·2배 축척), SPLINE, ELLIPSE, MTEXT, 반전(OCS -Z) 호, 각도 치수.

| 파일 | 형식·인코딩 | 읽기 결과 | R12 저장 3종(기본/근사 포함/치수 분해) ezdxf 감사 |
|---|---|---|---|
| flange_R12.dxf | AC1009, ANSI_949(CP949) | 원 11, 구멍 8-Ø14, 슬롯 bulge [0,1,0,1], 치수 3, 한글 정상 | 3/3 통과 |
| flange_R2000.dxf | AC1015, 표기 ANSI_1252·실제 CP949 | 위와 동일 + 보존 INSERT·SPLINE·ELLIPSE·MTEXT·각도치수(모두 표시 형상 생성), 반전 호 → 중심 (150,0), 90°~180° | 3/3 통과 |
| flange_R2010.dxf | AC1024, UTF-8 | 동일 | 3/3 통과 |
| flange_R2018.dxf | AC1032, UTF-8 | 동일 | 3/3 통과 |

- 저장 파일에서 원·호는 CIRCLE/ARC, 폴리선 호는 POLYLINE+VERTEX bulge로 유지됨(선분 분할 없음)을 ezdxf 객체 집계로 확인.
- ezdxf로 만든 치수 스타일은 문자 높이 0.25(ezdxf 기본값)라 화면에서 매우 작게 보이며, 이는 원본 스타일 값을 그대로 따른 결과입니다.

## 4. 성능 측정 (`npm run perf`)

측정일 2026-11-27, Intel(R) Xeon(R) Processor @ 2.10GHz 4코어, Chromium (Playwright 내장, headless), 화면 1600x900, 각 항목 3회 측정 중앙값(프레임 항목은 30프레임 중앙값). 시험 도면 구성: 선 40%·원 25%·호 20%·폴리선 15%.

| 항목 | 1,000개 | 10,000개 | 50,000개 |
|---|---|---|---|
| 불러오기 + 공간 인덱스 생성 | 2.0 ms | 16.4 ms | 128.9 ms |
| 전체 보기 그리기(1회) | 4.6 ms | 10.6 ms | 43.5 ms |
| 8배 확대 상태 그리기 | 0.1 ms | 0.5 ms | 2.5 ms |

| 화면 프레임 간격 중앙값(정밀 재그리기) | 16.7 ms | 16.3 ms | 61.6 ms |
| **드래그 이동 프레임 간격 중앙값(비트맵 재사용)** | 16.6 ms | 17.2 ms | 16.7 ms |
| 객체 선택(클릭) 1회 | 0.002 ms | 0.005 ms | 0.012 ms |
| 객체 스냅 계산 1회 | 0.011 ms | 0.034 ms | 0.109 ms |

- 측정 환경은 GPU 없는 headless Chromium(소프트웨어 그리기)이므로 일반 PC의 Chrome(GPU 가속)과 수치가 다를 수 있습니다. 실제 사용 PC에서는 관리자 설정 → 성능 측정으로 다시 잴 수 있습니다.
- 개선 이력(같은 환경): 5만 객체 전체 그리기 1,038ms → 44ms. 원인은 큰 Path2D에서의 `closePath()` 반복(프로파일러로 확인, 3.2초 소요)과 미세 객체 처리. 대형 도면 화면 이동 중 비트맵 재사용으로 드래그 프레임 16.7ms(60fps) 유지.

## 5. 보안·안정성 점검

| 항목 | 결과 |
|---|---|
| 비밀정보 | 앱에 API 키·토큰·서버 비밀번호 없음. 저장소·ZIP에 비밀정보 없음(검색 확인) |
| 관리자 비밀번호 | PBKDF2-SHA256 310,000회 + 16바이트 salt, 해시만 저장, 상수 시간 비교, 5회 실패 5분 잠금, 5분 무조작 재인증 |
| 한계(정직한 고지) | 브라우저 localStorage는 OS 보안 저장소보다 약함. PC 사용자가 개발자 도구로 해시를 지우면 재등록 가능 → 관리자 기능을 로컬 도구로 한정해 피해 범위를 제한 |
| 도면 데이터 | 외부 전송 없음(서비스워커도 같은 출처 파일만 캐시), 자동 저장은 이 PC 브라우저 IndexedDB |
| 원본 보호 | 열어 온 파일을 묻지 않고 덮어쓰지 않음(첫 저장 시 `_수정` 이름 제안) |
| 잠금/숨김 레이어 | 선택 단계와 트랜잭션 단계 이중 차단. 숨김 객체는 데이터·저장 파일에 유지 |
| 계산 불가 형상 | OFFSET 반지름 초과·자기교차·세그먼트 소멸, TRIM 교차점 부족 → 오류 메시지 후 원본 유지 |
| 미지원 DXF 객체 | 삭제 없이 보존·경고. R12에 없는 종류는 저장 시 사용자 선택(근사/제외)과 결과 보고 |
| 명령 중 예외 | 엔진이 잡아 메시지 표시 후 명령 종료, 문서는 마지막 확정 상태 유지 |

## 5.1 독립 코드 검토 결과와 조치

구현자와 분리된 검토자(별도 AI 검토 에이전트 — 외부 전문가 승인이 아님)가 기하·DXF·명령 엔진 코드를 읽고 재현 시험으로 12건을 지적했습니다. 모두 수정했고, `tests/unit/regressions.test.ts`(12개 시험)로 재발을 막았습니다.

| # | 심각도 | 지적 | 조치 |
|---|---|---|---|
| 1 | 높음 | 닫힌 폴리선 TRIM 시 시작 정점(u=0/u=n) 중복 절단점 → 객체 삭제·잘못된 조각 | 순환 매개변수 합치기, 길이 0 세그먼트 제거, 남는 조각 없으면 오류 |
| 2 | 높음 | 보존 객체의 한글 값이 R12 파일에 UTF-8 원문으로 기록(머리글 ANSI_1252와 불일치) | 원본 그룹코드의 문자열 값도 `\U+XXXX`로 기록 |
| 3 | 높음 | 실행취소 200단계 초과 시 명령 묶음 위치 어긋남 → PLINE 중복 생성 | 묶음 시작 위치 보정, PLINE 자체 확정 플래그 |
| 4 | 높음 | 레이어 이름 대소문자 불일치로 잠금 우회·LAYER 항목 중복 | 불러올 때 대소문자 무시로 레이어 표 이름에 맞춤, 저장 시 중복 제거 |
| 5 | 중상 | 자기교차하는 OFFSET 결과를 정상으로 반환(가공 경로 파고듦) | 결과 세그먼트 상호 교차 검사 → 오류 표시 후 원본 유지 |
| 6 | 중 | LINE/TRIM의 U가 명령 중 다른 변경(레이어 변경)을 되돌림 | 명령이 만든 커밋만 골라 되돌리는 `revertInGroup` |
| 7 | 중 | 명령 안에서 U로 취소한 선분이 명령 후 다시실행으로 되살아남 | 묶음 종료 시 묶음 안의 다시실행 기록 제거 |
| 8 | 중 | 문자 스타일(7)·폭 비율(41)·기울기(51)·치수 스타일 이름 손실 | 보존·재기록, 원본 STYLE·DIMSTYLE 표 항목 재기록, 참조 이름은 반드시 정의 |
| 9 | 중 | 도면공간 LWPOLYLINE 저장 시 제외, 폴리선 폭 손실 | 67=1 유지하여 변환, 폭(40/41/43) 보존 |
| 10 | 중 | 중복 정점이 있는 폴리선 OFFSET 거부 | 길이 0 세그먼트 제거 후 계산 |
| 11 | 낮음 | 꺼진 레이어 객체를 속성 창으로 수정 가능 | 트랜잭션에서 꺼진 레이어도 거부, 레이어 상태 변경 시 선택 정리 |
