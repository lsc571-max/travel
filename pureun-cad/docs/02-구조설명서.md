# 02. 구조 설명서 — 푸른캐드 V0

## 1. 실행 방식 선정

| 후보 | 장점 | 단점 | 결론 |
|---|---|---|---|
| **PC 중심 웹앱(PWA)** — TypeScript·React·Vite·Canvas 2D·IndexedDB | 설치 불필요, 무료 호스팅(GitHub Pages 등), 오프라인 캐시, 지시서 권장 환경 | 파일 덮어쓰기는 브라우저 권한 필요, 운영체제 보안 저장소 사용 불가 | **채택** |
| Electron 데스크톱 | 파일 접근 자유, OS 보안 저장소 | 설치 용량 100MB+, 업데이트·코드서명 비용 | 향후 필요 시 같은 소스로 포장 가능 |
| 네이티브(C++/Qt) | 최고 성능 | 개발 비용 큼, 오픈소스 CAD(GPL) 코드 재사용 불가 | 제외 |

- 서버 없음, AI API 없음, 도면은 외부로 전송하지 않음 → **운영 비용 0원**(정적 파일 호스팅 무료 한도 내).
- 런타임 의존성 3개만 사용: React(화면), rbush(공간 인덱스), qrcode-generator(공유 QR). 모두 MIT.

## 3. 핵심 설계

### 3.1 정밀도
- 모든 좌표·길이는 JS `number`(IEEE-754 64비트)로 저장. 저장·계산 단계에서 반올림하지 않는다.
- 화면 표시는 설정의 소수 자리(기본 4)로만 반올림(`fmtNum`). 속성 창은 값을 바꾸지 않으면 원래 64비트 값을 유지한다.
- DXF 저장은 왕복 가능한 최단 10진 표현(`dxfNum`)으로 출력하며 지수 표기를 피한다. 단위 테스트에서 `0.1+0.2`, `1/3`, `12.345678901234567`, `-2.5e-8` 등이 비트 단위로 같게 돌아오는지 확인.
- 원호 각도는 DXF와 같은 **도(°)** 로 저장하여 도↔라디안 변환 오차가 누적되지 않게 했다. 회전(ROTATE 90°)도 각도에 정확히 더한다.
- 0/90/180/270° 극좌표 입력, 수평·수직선의 교점은 삼각함수·나눗셈 오차 없이 정확한 값을 쓴다.

### 3.2 기하 데이터 유지
- 원은 CIRCLE, 호는 ARC, 폴리선 호는 bulge 값으로 저장. 다각형으로 바꾸지 않는다.
- 화면 근사(다각선)는 **표시 전용**이며 저장되지 않는다(매우 큰 반지름, 비균일 축척 블록 등).

### 3.3 문서·실행취소
- 객체는 불변 객체로 다루고, 변경은 트랜잭션(`doc.tx()`)으로만 한다. 트랜잭션은 객체별 [이전, 이후]를 기록.
- 명령 하나에서 생긴 여러 커밋은 `beginGroup/endGroup`으로 실행취소 1단계로 묶는다(예: COPY 여러 번, LINE 여러 선분).
- **잠긴 레이어 보호**: `TxBuilder.update/remove`가 잠긴 레이어 객체의 변경을 거부(이중 방어: 선택 단계에서도 제외). 새 객체 작성은 AutoCAD와 같이 허용.
- 꺼진 레이어 객체는 표시·선택·스냅에서 빠질 뿐 데이터에는 그대로 있다.

### 3.4 공간 인덱스와 화면 갱신
- `rbush`(R-tree)로 화면 영역·선택 상자·스냅 범위의 객체만 조회.
- 캔버스 3겹: ① 도면(문서·뷰 변경 시만) ② 선택 강조 ③ 오버레이(커서·미리보기·스냅). 마우스 이동은 ③만 다시 그린다(부분 갱신).
- 같은 색·선종류 객체는 하나의 `Path2D`로 묶어 한 번에 그린다. 1.5px보다 작은 객체는 점으로 표시.
- 대형 도면에서 화면 이동·확대 중에는 직전 비트맵을 옮겨 보여 주고, 멈추면(150ms) 정밀하게 다시 그린다.
- 측정 중 발견: 큰 `Path2D`에 `closePath()`를 반복하면 Chromium에서 매우 느려져(5만 객체 3초 이상) 사용하지 않도록 수정.

### 3.5 명령어 엔진
- 명령은 제너레이터 함수로 작성: `const p = yield { kind: 'point', prompt: '...' }`. 엔진이 마우스 클릭·좌표 입력·키워드를 해석해 재개한다.
- 입력 요청 종류: 점, 거리, 각도, 객체 선택(창/걸치기), 객체 하나, 문자열. 각 요청은 키워드(`[닫기(C) / 명령 취소(U)]`), 미리보기 함수, 기준점(고무줄·직교·직접 거리 입력)을 가질 수 있다.
- Esc 시 제너레이터를 종료(`return`)하여 `finally` 블록이 실행된다(PLINE은 그린 부분 유지).
- 명령 중 예외가 나면 메시지를 표시하고 명령을 끝내며 문서는 마지막 커밋 상태를 유지한다.

### 3.6 DXF
- 읽기: ASCII DXF(R12~R2018 시험). 이진 DXF·DWG는 오류 메시지로 안내.
  - 인코딩: R2007(AC1021)+ → UTF-8, 그 이하 → `$DWGCODEPAGE`(ANSI_949=CP949 등). 머리글이 ANSI_1252인데 실제 CP949인 파일도 한글 판별로 보정. `\U+XXXX` 해석.
  - 돌출 방향 (0,0,-1)인 호·원·폴리선(CAM에서 흔한 반전 호)은 좌우 반전으로 정확히 변환. 그 밖의 3D 방향은 보존 객체로 처리.
  - 미지원 객체: 원본 그룹코드 전체를 `preserved`에 보관, 종류별 개수를 사용자에게 알림. 표시 가능한 것은 표시 전용 형상을 만든다(편집·선택 불가, 스냅 가능).
- 쓰기: R12(AC1009). HEADER(ACADVER, DWGCODEPAGE, EXTMIN/MAX, LTSCALE), TABLES(LTYPE, LAYER, STYLE, DIMSTYLE), BLOCKS(보존 블록 + 치수 블록), ENTITIES.
  - 비ASCII 문자(한글)는 `\U+XXXX`로 기록(R12의 코드페이지 의존성 회피).
  - 보존 객체: R12에 있는 종류는 원본 그룹코드를 기록하되 R12에 없는 코드(핸들 5, 서브클래스 100, 102 그룹, 330/360, 확장데이터 등 0~79·210~239 이외)만 제외. R12에 없는 종류(MTEXT·SPLINE·ELLIPSE 등)는 저장 대화상자에서 **"근사 변환 포함" 또는 "제외"** 를 사용자가 고르며, 제외해도 열린 도면에는 계속 보존된다. LWPOLYLINE은 항상 정확히 POLYLINE으로 변환.
  - 치수는 형상 블록 `*Dn`과 함께 기록(AutoCAD 요구사항). "치수 분해 저장" 옵션은 CAM 전달용.

### 3.7 보안
- 비밀키·API 없음. 일반 설정에는 민감 정보가 없다.
- 관리자 설정: 설정창 머리의 설정 아이콘을 **첫 클릭부터 3초 안에 5회** 누르면 비밀번호 창. 최초 사용 시 기기별 등록(6자 이상, 확인 입력).
  - 저장: PBKDF2-SHA256, 무작위 16바이트 salt, 310,000회 반복, 해시만 `localStorage`에 저장. 원문 저장 없음, 상수 시간 비교.
  - 5회 실패 시 5분 잠금, 인증 후 5분 무조작 시 재인증, 종료 시 관리자 화면 닫힘.
  - 대체 진입(접근성): 키보드로 설정 아이콘에 초점을 두고 Enter를 5번 눌러도 동일하게 동작.
  - 한계: 브라우저 저장소는 OS 보안 저장소(Windows 자격 증명, Keychain 등)보다 약하며, 기기 사용자가 개발자 도구로 해시를 지울 수 있다. 그래서 관리자 기능은 로컬 도구(성능 측정, 저장 데이터 초기화, 비밀번호 관리)만 다루며 서버 권한은 없다.
- 공유 링크는 앱 주소만(쿼리·해시 제거) 포함한다.

### 3.8 확장 구조 (2단계 대비)
- `core`의 `entitySegs`(모든 곡선을 선/원호 세그먼트로 분해)는 윤곽 검출·중복 객체 정리·공구 경로 계산의 기반으로 그대로 쓸 수 있다.
- 명령은 `registry.ts`에 등록만 하면 메뉴·명령창에서 쓸 수 있다.
- AI 기능을 추가할 경우 브라우저에 키를 두지 않고 별도 서버(인증·호출 제한)를 두는 구조로 설계해야 한다(현재 미포함).
