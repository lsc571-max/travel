# 변경 기록 — 푸른 교수 일정관리

## V1.2 — 2026-11-27 (구글 할 일 연동)
**변경 사항**
- 구글 할 일(Google Tasks) 연동: 오른쪽(휴대폰은 위쪽) 패널에 「할 일」 목록 — 체크로 완료/되돌리기, 눌러서 수정, 「+ 할 일」로 추가, 삭제(확인 후)
- 마감일 있는 할 일은 달력 그 날짜에 ☐(완료는 ✓·줄긋기)로 표시, 눌러서 수정. 마감 지난 할 일은 빨간 글씨
- 마감은 **날짜만** 연동 (구글 할 일 API가 시간을 주고받지 않음). 수정할 때는 바뀐 칸만 보내 다른 기기 변경을 덮어쓰지 않음
- 여러 할 일 목록 지원(새 할 일은 목록 선택, 목록 옮기기는 구글 할 일에서), 「완료 지우기」로 숨긴 항목은 표시 안 함
- 설정에 「구글 할 일 표시」 켜기/끄기. 할 일 권한을 허용하지 않아도 일정 기능은 그대로이고 할 일 칸에 안내 표시
- 권한: `tasks` 추가 (콘솔: Google Tasks API 사용, 데이터 액세스에 `.../auth/tasks`). 처음 연결 때 권한 동의 화면이 한 번 더 나옴
- 보안 헤더(CSP) `connect-src`에 `https://tasks.googleapis.com` 추가. 미리보기 서버도 `firebase.json`과 같은 헤더를 붙여 시험에서 CSP 위반을 잡도록 함
- 연결 끊기 시 할 일 사본(localStorage `pc.tasks`)도 삭제

**검증 결과 (배포 전)**
- 단위 테스트 29개 통과(할 일 9개 추가), TypeScript 검사·빌드 성공, 브라우저 기능 테스트 40개 통과(할 일 10개 추가, 가짜 Google 서버)
- CSP에서 할 일 주소를 빼면 할 일 시험 8개가 실패하는 것을 확인 → 시험이 보안 헤더를 실제로 검사함

**복원 기준**: V1.1 소스는 커밋 `0406513`, 드라이브 `V1.1/` 압축본. 배포 문제는 Firebase Hosting 콘솔에서 V1.1 배포로 롤백.

## V1.1 — 2026-11-27 (클라이언트 ID 포함·배포 준비)
**변경 사항**
- Google Cloud 프로젝트 `pureun-schedule` 생성, Calendar API 사용, 동의 화면(외부·테스트, 권한 `calendar.events` 하나), 웹 클라이언트 「일정관리 웹앱」
- `.env.production` 에 OAuth 클라이언트 ID 기본 포함 (공개 식별자. 클라이언트 보안 비밀번호는 저장하지 않음)
- 버전 표시 V1.1 (`config.ts`, `version.json`, `sw.js`, `package.json`)
- 브라우저 시험: ID를 비운 시험 전용 빌드를 `test-results/dist` 에 따로 만들어 실행 (배포용 `dist/` 는 그대로), Windows에서도 실행되도록 vite를 node로 직접 실행

**검증 결과 (배포 전)**
- 단위 테스트 20개 통과, TypeScript 검사·배포용 빌드 성공, 브라우저 기능 테스트 30개 통과(가짜 Google 서버)

- 생략: 로컬(`localhost:4173`) 실계정 시험 — 조작하던 크롬이 빌드한 PC에 접속할 수 없어 배포 주소에서 시험

**요금**: 새 프로젝트가 결제 계정에 자동 연결되어 있어, 사용자 결정으로 연결을 유지함 (Firebase Blaze 종량제. 개인 사용은 무료 한도 안 예상)

**복원 기준**: V1 소스는 커밋 `5f8db88` (V1 앱 코드는 `76d7fa0`). 배포 후 문제는 Firebase Hosting 콘솔에서 이전 배포로 롤백.

## V1 — 2026-11-24 (1단계 첫 실행 버전)
**변경 사항**
- 구글 계정 로그인(Google Identity Services, 토큰은 메모리에만 보관)
- 월간·주간·일간·목록 보기, 오늘 일정·다가오는 7일 일정 패널, 날짜 빠른 이동
- 일정 등록·수정·삭제, 종일 일정, 반복(매일·매주 요일·매월·매년, 종료일·횟수), 반복 일정 "이 일정만 / 전체" 수정·삭제
- 카테고리(개인=파랑·학교=초록·회의=노랑·출장=빨강), 구글 11색, 중요도(보통/★/★★), 알림
- 대한민국 공휴일 캘린더 표시(읽기 전용)
- 다른 기기에서 먼저 바뀐 일정 덮어쓰기 방지(etag 확인창)
- 밝은/어두운/시스템 테마, 글자 크기, 주 시작 요일, 기본 보기
- 숨겨진 관리자 설정(3초 안 5회 + PBKDF2 비밀번호, 5회 실패 시 5분 잠금, 10분 무조작 자동 닫힘)
- 공유 링크·QR코드, 버전 정보·업그레이드 안내, PWA(홈 화면 설치·오프라인 읽기)

**구상서(V0)와 달라진 점**
- 증분 동기화(syncToken) 대신 "보이는 기간만 불러오기 + 5분 캐시" 방식: 반복 일정 전개를 Google에 맡겨 더 단순하고 정확함. 호출 수는 하루 수백 회 수준으로 무료 한도와 무관.
- 앱 설정은 이 기기에만 저장(Drive 동기화는 첨부 기능과 함께 2단계). 이에 따라 1단계 권한은 `calendar.events` 하나만 요청.
- 사용자 정의 카테고리 추가는 2단계로 이동(기기 간 동기화가 필요하므로).

**검증 결과**
- TypeScript 엄격 검사 통과, 단위 테스트 20개 통과(Vitest), 브라우저 기능 테스트 30개 통과(Playwright, 가짜 Google 서버)
- 배포용 보안 헤더(CSP) 적용 상태에서 화면 오류 없음 확인 (달력 아이콘 글꼴 허용 추가)
- 독립 AI 코드 검토 반영: 반복 일정 전체 시간 변경 시 지운 회차 부활 방지, 늦게 온 반복 정보가 입력 내용을 지우던 문제, 저장 직후 오래된 새로고침 결과가 새 일정을 가리던 문제, 비밀번호 재설정 시 계정 확인(처음 연결한 계정 해시와 비교), 서비스워커가 오류 페이지를 저장하던 문제, 잠금 해제 후 확인 버튼 자동 활성화, 시작일 변경 시 반복 요일 자동 변경
- npm audit 취약점 0건, innerHTML·비밀키 패턴 없음
- 미검증: 반복 일정 '전체' 날짜·시간 변경 시 Google이 기존에 개별 수정된 회차를 어떻게 처리하는지, 실제 Google 계정 로그인·실제 Calendar API·공휴일 캘린더 실제 조회·Firebase 배포·실제 iPhone/Android 설치

**복원 기준**: 문제가 생기면 Firebase Hosting 콘솔에서 이전 배포로 롤백. 일정 데이터는 구글 캘린더에 있으므로 앱 버전과 무관.
